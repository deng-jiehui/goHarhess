# 结构化路由与模型追问：实现和验收

日期：2026-10-19。范围：AutoResearch 应用；goHarness 框架未修改。

## 1. 模型与代码各负责什么

| 事项 | 当前实现 |
| --- | --- |
| 选择业务路线 | `understand_goal` 模型输出 `GoalDecision` JSON；应用校验后提交到 State |
| 是否提问、问什么、给哪些选项 | 当前业务模型调用真实 `ask_user` 工具；不再按空 scope 强制追问 |
| 条件边 | 只读取已提交状态，映射到声明好的节点；不调用模型、工具或数据库 |
| 暂停与恢复 | `clarify` ToolsNode 内调用 `graph.Interrupt`；Resume 后把答案作为原调用的工具结果返回 |
| 文件和命令操作 | 工作区模型选择已有七个工具；应用继续控制路径、批次、预算与原有写入确认 |

`select_research_route` 已移除，路由不再以工具调用表达；`request_clarification` 只是早期讨论中的名称，实际交互工具统一为 `ask_user`。

## 2. 业务路由协议

```json
{"route":"focus","scope":"检索增强系统","save":true}
```

三个字段必填；`save` 为布尔值，`scope` 可以为空。`route` 只允许 `focus`、`notes`、`answer`、`workspace`、`boundary`。模型不能传入任意节点名。

使用普通 JSON 提示词与 `llm.NewStructuredOutput[GoalDecision]` 本地结构校验，不依赖服务商原生 JSON Schema 能力。路由请求不携带工具定义。只接受单条助手 JSON 消息，兼容整段 JSON 外的 json 代码围栏；拒绝说明文字、工具调用、未知字段、错误类型及未知路线。

格式不合格时携带具体校验错误重试一次；再次失败则结束执行，不按用户输入中的关键词回退。关键词决策仅存在于离线 fixture，不参与真实模型容错。

## 3. ask_user 协议

模型得到由 `tool.New[AskUserArgs, AskUserResult]` 生成的工具定义，例如：

```json
{"question":"第一轮实验可使用哪些资源？","choices":["本地 CPU","实验室 GPU"]}
```

- `question`：1–1000 个 Unicode 字符。
- `choices`：可省略或为空；提供时为 2–6 项，每项 1–120 个字符，不允许空项或重复项。
- 禁止未知参数；用户、项目、会话、中断 ID 与执行批准均不由模型提供。
- 一批只能有一个 `ask_user`，不能夹带文件读取、写入或命令调用。

前端沿用现有交互卡：单选按钮、可编辑选项和独立可编辑回答框。最终提交的是用户确认的文本，允许修改建议答案或完全自行填写。当前每次只问一个问题，多选、多问题问卷仍属后续扩展。

工具内产生如下 Graph 中断载荷：

```json
{"kind":"clarification","question":"第一轮实验可使用哪些资源？","choices":["本地 CPU","实验室 GPU"],"allow_custom":true,"placeholder":"选择、编辑选项，或输入自己的回答"}
```

用户通过现有 Resume API 提交非空文本；工具返回 `{"answer":"单卡，预算两小时"}`，应用核对原调用 ID、工具名称及成功状态后，将结果追加到原业务模型消息。

## 4. 提交和恢复顺序

1. 当前业务模型生成调用，PostHandler 校验完整批次。
2. 将调用消息、调用 ID、问题参数和返回节点写入 `InteractionState`，提交 State。
3. 进入独立 `clarify` ToolsNode，执行已固定的 `ask_user`，产生中断。TurnService 使用同步检查点。
4. 真实回答到达后恢复相同工具调用；重放工具节点时不重新请求模型生成问题。
5. 把配对结果追加到原 `DraftMessages` 或 `Workspace.Messages`，保留 Route、Scope 和 SaveRequested。
6. 按已保存的 ReturnNode 回到原业务节点，不重跑 `understand_goal`。

已确认问题与答案保存在当前 State，并供本轮最终答复使用；完成时写入唯一最终助手消息的 `Extra["autoresearch.confirmed_answers"]`。下一轮读取已提交的正式消息后恢复这些答案，前端仍只显示一条最终助手消息。

当前上下文使用最近 6 条正式消息、最多 10 条笔记摘要；较早约束不保证永久驻留模型窗口。没有新增长期记忆或论文证据存储。

## 5. 批次和执行限制

| 限制 | 当前行为 |
| --- | --- |
| 路由格式修复 | 最多 1 次 |
| 已完成的追问 | 每轮最多 3 次；模型继续提问时明确失败，不无限暂停 |
| 工作区模型调用 | 最多 8 轮，包含提问后的继续调用 |
| 工作区工具调用 | 最多 24 次，包含工作区中的 ask_user |
| 纯读批次 | 一条助手消息中最多 4 个调用，调用 ID 非空且不重复 |
| ask_user / write_file / apply_patch / run_shell | 每个调用独占一批；整批先校验后执行 |
| 非法工具批次 | 直接报错，整批不执行；尚未实现协议错误回传后的模型修正 |
| Graph | 最多 48 步；worker 每个执行段 5 分钟，等待输入不占执行段 |

普通文本起草节点只得到 `ask_user`，不获得文件工具；压缩和最终答复节点没有工具定义。工作区模型获得七个既有工作区工具加 `ask_user`。不存在统一的累计模型调用计费预算；上述轮次和步数上限是当前实际限制。

澄清答案只表示用户事实或偏好，不作为文件修改批准。现有 `write_file` / `apply_patch` 仍通过独立确认载荷中断；受限 shell 的确认后执行闭环不在本次改造范围。

## 6. 版本与范围

图定义：`autoresearch-phase2-graph-v2`。StateCodec：`autoresearch:research-state`，版本 2。

旧版未完成轮次不能套用新版交互协议。worker 在构造图、调用模型或访问检查点前返回 `recovery_required`，要求结束旧轮次后重新发送；项目资料和正式历史保留。没有实现旧版图运行器或自动迁移旧 pending。

本轮没有实现独立的 `read_project/list_notes/read_note/save_note` 工具目录。项目与笔记仍由 `load_context` 注入，保存仍由 `persist_note` 调用现有用例。工作区路线也尚未增加复合任务调度或额外笔记保存路径。学术 MCP、服务器实验、完整 shell 授权、结构化证据产物等按后续任务推进。

### 项目笔记管理（2026-10-19）

笔记属于项目，在各会话之间共享，不等同于本轮新生成的回答。新建会话或修改研究主题时保留已有笔记，界面注明来源与保存时间，并解释其作用。当前用户目标优先于旧笔记，相关性由模型判断，不通过关键词写死研究领域。离线示例也围绕当前输入生成流程样例，不再套用代码修复模板。

新增 `GET /api/projects/{projectID}/notes` 和 `DELETE /api/projects/{projectID}/notes/{noteID}`，均由可信 Scope 限定归属。迁移 004 添加 deleted_at，列表和后续新轮上下文排除已删除笔记；保留保存幂等身份，旧轮重放保存返回冲突，不自动恢复已删除笔记。已有聊天记录、冻结上下文和检查点不被改写。前端提供单次确认删除，不要求输入名称；会话内容独立滚动。

## 7. 自动验收

后端测试使用 HandlerModel、真实编译图和临时内存/SQLite 检查点，覆盖：

- 空 scope 由模型直接回答；非代码修复主题动态提问。
- 原问题和选项进入 pending；重建图后继续原节点，不重生成问题或重跑路由。
- answer、notes、workspace 连续两次提问；工作区回答后继续读取文件。
- 当前答复和经 SQLite 持久化后的下一轮都能获得真实确认答案。
- 路由格式修复、未知路由/字段/类型拒绝、非法问题拒绝和追问预算。
- 混合提问与写入批次整批拒绝，文件不创建。
- 旧图版本在执行前被拒绝；既有笔记保存、压缩和写入确认仍可用。

浏览器 E2E 使用测试启动器的独立数据库和 fixture，验证选项选择、编辑后同步回答、提交恢复、保存和打开笔记。未使用真实 API Key 或付费模型。

## 8. 前端手动检查

1. 重启后端，模型设置选择离线演示，创建新会话。
2. 发送“请帮我整理研究方向并保存为项目笔记”。应看到“这轮研究希望优先推进哪一步？”及两个可编辑选项。
3. 选择“先比较研究方向”，修改选项文字，确认回答框同步；也可直接填写“希望两周内完成一份小规模实验方案”。
4. 等待回答时刷新页面，问题保持；提交后继续原轮，保存一条笔记，最终完成。
5. 展开并打开项目笔记；下一轮继续讨论已确认条件。离线回答仅用于验证流程。

真实模型模式可发送“我研究检索增强生成，请先给三个适合本科生的方向，不用追问”；也可发送“为我的检索实验制定计划，缺少会改变方案的信息时用提问工具询问我”。是否提问和具体问题由模型决定，不保证每次都出现固定问题。模型必须支持标准工具调用，提示词中写出工具名不算实际调用。
