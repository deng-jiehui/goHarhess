**状态：** 阶段 01 已验收；阶段 02 MVP 已实施并验收；阶段 03 基础论文库闭环已实施，真实 MCP 与证据定位继续推进。
**更新日期：** 2026-10-17。  
**当前交付：** 本地项目工作台，见[阶段 01 验收](phases/01-workspace/ACCEPTANCE.md)。

## 1. 怎么推进

按用户能够体验的完整能力划分阶段。每个阶段都要有输入条件、独立演示路径和验收记录；设计、实施、验收分别记录，写好文档不代表完成开发。

每次进入一个阶段，先写该阶段的 `DESIGN.md`，明确范围、流程、数据、接口和故障处理；再写 `IMPLEMENTATION.md`，明确文件、任务顺序、行为用例和检查命令。完成阶段验收后，再根据实际实现细化下一阶段。

阶段 01 的设计、实施和验收已独立记录，阶段 02 已编写设计和实施计划。阶段 03–06 的旧任务拆解保留为参考草案，进入相应阶段时再拆出独立文档。阶段 07–08 只确定扩展目标，不提前锁定部署组件或桌面框架。

## 3. 各阶段边界与验收

### 阶段 01：先把项目工作区保存下来

**用户场景：** 学生创建“代码缺陷修复 Agent”研究项目，填写研究问题，新建“方向讨论”和“论文阅读”两个会话，关闭并重新打开后仍能找到它们。

- 范围：独立 Go 模块、配置、SQLite、项目与会话 API、React 三栏工作区、研究设置。
- 本阶段只管理会话元数据；消息执行、论文、方向和实验在对应阶段接入。
- 演示：创建项目 → 编辑研究问题 → 创建并重命名会话 → 刷新 → 重启后读取 → 归档项目。
- 验收：数据持久化、作用域隔离、项目版本冲突、API 与页面一致；后端和前端均可独立启动验证。

### 阶段 02：让同一个 Agent 真正工作

**用户场景：** 用户让 Agent 读取当前项目并保存研究笔记，界面能展示工具调用和结果；需要用户补充信息时暂停，确认后继续。

- 范围：应用直接定义 Graph 主图与可持久 State、项目上下文、项目/笔记/追问工具、消息持久化、后台 worker、每轮完整检查点、SSE 续读、失败重试与结束。
- 演示：读取项目/笔记 → 检查研究范围 → 追问暂停 → 重启并回答 → 生成/检查关注点 → 保存并核对；另一会话只读查询。
- 验收：同会话执行互斥，浏览器断开不结束后台执行；消息与事件可恢复，不重复追加文本或重复提交新 Turn。
- 设计重点：[详细业务图](phases/02-agent-runtime/GRAPH_DESIGN.md) 定义关注点、笔记整理和项目问答三条路线、有限修复、写入前后门槛与公开产物；保留独立轮身份、正式历史和笔记防重，复用现有 callback。

### 阶段 03：让论文成为项目资料

**用户场景：** 用户通过 arXiv MCP 搜索论文，把选中的论文存入项目，添加标签和笔记，再查看与原文对应的证据片段。

- 范围：第一真实学术 MCP、来源适配、论文去重、归档、阅读、笔记、证据与项目内检索。
- 演示：搜索 → 导入两次验证去重 → 添加笔记 → 查看原文片段 → 在另一会话继续使用。
- 验收：来源与版本可追踪；不同项目的笔记隔离；引用片段能在冻结文本中定位；只有摘要时明确标记。
- 设计重点：MCP 是工具来源，项目归档与证据规则由应用管理。Zotero 不阻塞本阶段。

### 阶段 04：完成第一条研究闭环

**用户场景：** 用户提出研究问题，Agent 生成方向提案和检索计划，用户审核候选论文，最后得到证据矩阵及带引用的报告。

- 范围：方向提案与确认、项目设置快照、长调研任务、候选审核、恢复、证据矩阵、报告和 CLI fixture 调研。
- 演示：研究问题 → 方向确认 → 计划 → 候选审核 → 调研 → 查看并追溯报告引用。
- 验收：修改研究范围产生可辨识的新版本；审核拒绝的论文不进入分析；恢复不重复归档已完成结果；事实与推断分开。
- 设计重点：在共享理解/范围流程后接入检索计划、候选审核、逐篇证据、综合与引用检查，形成专用路径；固定批处理与嵌套恢复在本阶段单独验证。

### 阶段 05：把研究连接到实验室服务器

**用户场景：** 用户要求复现一篇论文，或在自己的代码和数据上验证一个想法。Agent 生成计划，经确认后运行，并把结果回写项目。

- 范围：服务器档案、实验计划、版本审批、SSH Runner、本机 Connector、幂等提交、日志、监控、指标与产物。
- 演示：预检查 → 展示代码和资源计划 → 确认 → 提交 → 断开再连接 → 查看指标和比较结论。
- 验收：旧审批不能执行新计划；提交响应丢失后先核对；关闭页面后实验继续；执行成功与复现结论分别记录。
- 设计重点：服务器不强制安装常驻 Runner；长任务由已验证的 tmux 或既有调度器托管。用户侧 Connector 通过主动连接传递任务。

旧依赖允许部分实验任务在阶段 02 后开展；当前按顺序推进，降低同时设计多个子系统的负担。

### 阶段 06：形成完整的本地作品

**用户场景：** 新用户按说明启动应用，从项目会话完成调研和实验，并能处理常见失败与恢复。

- 范围：跨阶段故障验证、完整端到端演示、构建和启动说明、配置样例、诊断与验收记录。
- 演示：在干净数据目录启动 → 完成调研 → 提交实验 → 重启恢复 → 查看结果与来源。
- 验收：离线 fixture、真实模型、真实学术 MCP、真实 SSH 的验证结果分别记录；没有验证的外部能力明确标记；依赖和启动步骤可复现。
- 设计重点：各阶段都做本阶段测试，本阶段负责跨模块和交付验证。

### 阶段 07：服务端部署

**用户场景：** 学生从不同电脑登录同一研究服务，查看自己的项目，并通过个人 Connector 访问实验室服务器。

- 范围：登录认证、项目权限、用户数据隔离、HTTPS 与连接鉴权、持久任务归属、用户配额、备份恢复、部署配置。
- 演示：两个用户各建项目 → 互相访问被拒绝 → 连接各自 Connector → 重启服务后继续任务。
- 验收：API、SSE、产物、任务、检查点和 Connector 均校验归属；不能仅更改监听地址就宣称支持多人服务。
- 进入时决策：先确定单实例还是多实例。单实例可继续使用 SQLite；多实例再设计共享数据库、文件存储和任务协调。

### 阶段 08：桌面客户端

**用户场景：** 用户安装桌面应用，直接使用本地工作区，或登录远程服务，连接本机资料和实验室服务器。

- 范围：复用 React 界面、桌面壳、本地服务生命周期、服务地址与登录、本机 Connector 装配、凭据存储、安装包。
- 演示：安装启动 → 打开本地项目 → 重开应用 → 在远程模式下登录并选择用户侧 Connector。
- 验收：桌面壳通过相同应用 API 使用业务能力；用户身份和 SSH 私钥不进入页面或模型上下文；退出时明确区分关闭窗口与取消任务。
- 进入时决策：比较 Wails / Tauri 等方案，确认目标操作系统与更新方式；当前不增加桌面依赖。

## 4. 阶段文档怎么放

所有资料和后续源码仍留在本项目文件夹。

```text
ROADMAP.md                         阶段目标、依赖和完成条件
PRODUCT_REQUIREMENTS.md             整体需求基线
ARCHITECTURE.md                     整体职责与扩展边界
TECH_STACK.md                       整体技术选择
IMPLEMENTATION_TASKS.md             全局任务编号、需求映射
tasks/CONTRACTS.md                 跨阶段接口与一致性约定
tasks/02-agent-runtime.md          阶段 02 新文档入口
tasks/03-*.md ... 06-*.md           尚未进入阶段的任务参考
phases/01-workspace/
  DESIGN.md                       阶段 01 设计
  IMPLEMENTATION.md               阶段 01 实施
  ACCEPTANCE.md                   阶段 01 实际验收记录
phases/02-agent-runtime/
  DESIGN.md                       阶段 02 设计基线
  IMPLEMENTATION.md               阶段 02 实施计划
```

进入后续阶段时，分别创建 `03-paper-library`、`04-auto-research`、`05-remote-experiments`、`06-local-release`、`07-server`、`08-desktop` 目录，并在其中单独编写两份文档。尚未创建的文件不列为可执行计划。

`DESIGN.md` 说明用户流程、职责、数据与接口、失败恢复、部署边界和验收用例；`IMPLEMENTATION.md` 只拆该阶段任务，列出文件、输入输出、步骤和验证方式。实现后再增加 `ACCEPTANCE.md`，记录实际命令、结果与限制，不能预填通过。

整体需求定义目标，整体架构与契约约束跨阶段边界；阶段文档在这些边界内细化。若阶段设计需要改变公共约定，同步修改契约及受影响的任务参考，不能各写一套。
