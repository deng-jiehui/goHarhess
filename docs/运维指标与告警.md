# 指标与告警建议

`extensions/otel.Metrics` 把观测事件映射为 OTel 指标，全部从现有事件的
`Duration`、`Usage`、`Err` 与 `Attrs` 推导，没有新增发射点；`limits` 的
各组件通过可选的 `Meter` 选项自行上报。指标名前缀统一为 `goharness.`。

```go
observer, err := otel.Metrics(meter, otel.MetricsConfig{
    TenantLabelMax: 32, // 0 关闭租户标签
    Observables: []otel.ObservableSource{
        {Name: "observer.dropped", Description: "dropped events",
         Labels: map[string]string{"observer": "events"},
         Value:  func() int64 { return int64(async.Dropped()) }},
        {Name: "redis.logcache.size", Description: "log view cache entries",
         Value: func() int64 { return int64(store.LogCacheEntries()) }},
        {Name: "redis.logcache.evictions", Description: "log view cache evictions",
         Value: func() int64 { return int64(store.LogCacheEvictions()) }},
    },
})
ctx = observe.With(ctx, observer)

bulk := limits.NewBulkhead[[]schema.Message, []schema.Message](runnable,
    limits.BulkheadConfig{MaxConcurrent: 32, MaxQueue: 128, Meter: meter})
```

## 指标清单

| 指标 | 类型 | 标签 | 来源 |
| --- | --- | --- | --- |
| `goharness.run.active` | 增减计数 | agent（可选 tenant） | run 开始/结束事件 |
| `goharness.run.duration` | 直方图（秒） | agent、status、（可选 tenant） | run 结束事件 |
| `goharness.node.duration` | 直方图（秒） | node、status | node 结束事件 |
| `goharness.llm.duration` | 直方图（秒） | model、status | llm 结束事件 |
| `goharness.llm.tokens` | 计数 | model、direction（input/output/reasoning/cache_read/cache_write） | llm 结束事件 Usage |
| `goharness.tool.duration` | 直方图（秒） | tool、status | tool 结束事件 |
| `goharness.checkpoint.save.duration` | 直方图（秒） | store、status | checkpoint save 事件 |
| `goharness.checkpoint.conflicts` | 计数 | store | checkpoint 错误事件（`state.ErrConflict`） |
| `goharness.interrupts` | 计数 | agent（可选 tenant） | interrupt 事件 |
| `goharness.limits.bulkhead` | 观察值 + 计数 | state（inflight/queued/rejected） | `limits.Bulkhead` 的 Meter |
| `goharness.observer.dropped` | 观察值 | observer | `AsyncObserver.Dropped()` 经 Observables |
| `goharness.redis.logcache.size` / `.evictions` | 观察值 | 无 | `RedisStore.LogCacheEntries/Evictions` 经 Observables |
| `goharness.retrieval.*` | 直方图/计数 | stage | RAG 波次落地时补充 |

## 标签基数规则

- **用户 ID、会话 ID、运行 ID 永远不进指标标签**，只进 trace 属性。
- `status` 只取 `ok`/`error` 两值；`node`/`tool`/`model` 用声明名，
  不带调用参数。
- 租户标签默认关闭；`TenantLabelMax` 封顶——前 N 个出现的租户保留
  独立标签，其余合并为 `other`。时间序列上界为
  `run 指标 × agent 数 × (TenantLabelMax+1)`。

## 告警建议

阈值用第零波基线（`docs/benchmarks/pre-stage6.md`）作初始参照，
按各自服务的 SLO 再调。

| 告警 | 条件 | 含义与动作 |
| --- | --- | --- |
| 检查点冲突率上升 | `rate(checkpoint.conflicts[5m])` 相对 run 速率持续升高 | 同会话并发写入异常或存储层重试风暴；查入口去重与 `ErrConflict` 处理 |
| 锁丢失 | 应用侧分布式锁续租失败计数 > 0 | 锁 TTL 过短或 GC 停顿；锁不在框架内，由接入方上报 |
| 限流/舱壁拒绝 | `increase(limits.bulkhead{state="rejected"}[5m]) > 0` 持续 | 到达容量边界；扩并发、扩副本或调 `MaxConcurrent/MaxQueue` |
| 舱壁排队积压 | `limits.bulkhead{state="queued"}` 持续接近 `MaxQueue` | 容量将满，即将开始拒绝；同上 |
| 运行耗时尾延时 | `histogram_quantile(0.99, run.duration)` 超过服务 SLO | 看 node/llm/tool 直方图定位慢环节 |
| 检查点保存变慢 | `checkpoint.save.duration` p50 明显上移（Redis 基线约 0.9ms@h200、3.8ms@h1000） | 会话历史过长或 Redis 事件循环受压；考虑裁剪历史或分片 |
| 观察者丢弃 | `observer.dropped` 增量 > 0 | `observe.Async` 队列溢出，观测正在丢事件；加大 buffer 或换同步观察者 |
| Token 费用异常 | `llm.tokens{direction="output"}` 增速突升 | 循环失控或上下文膨胀；配 `MaxLLMCalls` 与应用侧预算 |
| 在途运行泄露 | `run.active` 不随流量回落 | 运行未正常收尾（挂起、死锁）；看 interrupts 与慢消费者告警 |

## 看板建议

- 每个 Agent：请求量、`run.duration` 分位、错误率（status=error 占比）。
- 每个模型：`llm.tokens` 按 direction、`llm.duration` 分位。
- 存储：`checkpoint.save.duration` 分位、`checkpoint.conflicts` 速率。
- 容量：`limits.bulkhead` 三个状态值、`run.active`。
- 检索（落地后）：`retrieval.duration` 按 stage、`retrieval.cache.hits`。
- 健康：`observer.dropped`、`redis.logcache.evictions` 突增说明
  `LogCacheSize` 相对活跃会话数偏小。
