# 多用户接入指南

从传统后端的视角看 goHarness：框架保证**并发正确、容量可调、可排空、
租户隔离**；认证、额度、会话串行化属于应用或网关，框架提供接缝与
兜底。完整参考实现见 `extensions/examples/server`。

## 请求装配顺序

```
认证（JWT/网关）→ tenant.With → 额度检查（应用）→ 会话串行化（应用）
→ Bulkhead → Agent（模型：重试+限流装饰；存储：租户装饰器+Redis）
→ SSE 输出（stream.Config.SendTimeout 保护）
```

```go
subject := tool.Subject{TenantID: claims.Tenant, ID: claims.User}
ctx, err := tenant.With(r.Context(), subject)   // 校验失败 → 401
out, err := bulk.Invoke(ctx, input, agent.WithCheckpoint(store, sid))
```

`tenant.With` 一次性做三件事：写入工具主体、观测元数据
（`tenant_id`/`user_id`）、租户作用域。`tenant.NewStore` 装饰器把
存储访问钉在该租户前缀内，越权 key 直接拒绝。

## 错误到 HTTP 状态码

| 条件 | 错误 | 状态码 | 说明 |
| --- | --- | --- | --- |
| 缺少或无效作用域、认证失败 | `tenant.ErrNoScope` 等 | 401 | |
| 越权访问他人会话 | `tenant.ErrTenantMismatch` | 403 | |
| 会话被占用（应用自己的串行化） | 应用自定义错误 | 409 | 可带 `Retry-After` |
| 并发更新冲突 | `state.ErrConflict` | 409 | 客户端可重试 |
| 会话有未完成运行 | `state.ErrUnfinishedRun` | 409 | 响应体说明应 Resume 或显式放弃 |
| 运行挂起等待输入 | `graph.ErrInterrupted` | 202 | 响应体带问题 ID 与内容 |
| 运行已被放弃 | `graph.ErrRunAbandoned` | 409 | |
| 服务过载 | `limits.ErrOverloaded` | 503 | 带 `Retry-After` |
| 缺少检查点配置 | `graph.ErrCheckpointRequired` | 500 | 部署配置错误 |
| 慢消费者 | `stream.ErrSlowConsumer` | 连接关闭 | 记日志与指标 |
| 客户端取消 | `context.Canceled` | 无响应 | |

## 关键边界

- **审批挂起**：`graph.Interrupt` 返回 `InterruptedError`，响应 202 带
  问题 ID；审批结果经 `agent.Resume` + `agent.WithResume(id, answer)`
  回灌。需要检查点存储；审批场景用 `agent.WithSyncPersist`。
- **同会话并发**：框架不排队同一会话的并发 `Invoke`——恰好一个成功，
  其余得 `ErrUnfinishedRun`/`ErrConflict`（契约清单 L 节）。串行化做法
  见[对接说明](integration.md#会话串行化)。
- **幂等**：请求头 `Idempotency-Key` 由应用实现（参考服务用 Redis
  `SET NX`），不进框架。
- **过载**：`Bulkhead` 满且不排队时立即 503 + `Retry-After`，不阻塞；
  排队只削短期毛刺。
- **SSE**：事件流经 `stream.Config{Buffer, SendTimeout}`；慢消费者在
  `SendTimeout` 内终止运行，协程回落，不拖垮实例。

## 观测

`observe.With(ctx, otel.Observer(...))` + `otel.Metrics`：run/LLM/工具/
检查点事件统一带 `tenant_id`、`agent`、`checkpoint.store` 标签；
SSE 通道上的公共事件可用 `stream.SuppressEvents`/`ContextFilter` 裁剪。
