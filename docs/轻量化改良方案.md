## 一、目标与非目标

### 目标

做一个**可观测、轻便、类似 LangGraph 的 Go Agent 框架**，功能不求多，但要让使用者用得简单，并覆盖大多数场景：

1. **可观测**：一行接入日志或 OpenTelemetry，一次运行的调用树、耗时、token 用量都能直接看到。
2. **易用**：3 节点图和 ReAct 图的代码量接近 LangGraph，类型错误尽量在编译期暴露。
3. **轻便**：核心包体量下降，用户只引入核心时不带上 RAG、子 Agent 管理等能力。
4. **可展示**：深度能力（检查点恢复、嵌套审批、并行超步）不丢失，以可选扩展和设计文档的形式保留。

### 非目标

- 不追求与 LangChain、LangGraph 的功能对齐。审查报告第四部分里“对齐 LangChain v1”的条目不再作为目标。
- 不在本方案中实现新的 Provider、长期记忆、Handoff、Swarm 等能力。
- 不承诺性能提升。性能只要求不退化。

## 三、设计原则

1. **一个概念一个入口。** 观测、配置、并行各只留一种方式。
2. **先新增，后切换，最后删除。** 每个阶段先让新路径可用并通过测试，再删旧路径，任何时刻都能回退。
3. **核心最小，深度外移。** 不属于“编排 + 观测”的能力放到扩展；暂时不能外移的先冻结，不再扩展。
4. **每阶段可独立合并。** 每阶段结束时两个模块的 `go build`、`go vet`、`go test ./...` 全绿，基准不明显退化。
5. **文档即产品。** `docs/` 顶层只放用户文档，过程文档归档。

## 五、关键设计

### 5.1 统一观测：`pkg/observe`

一个事件类型，一个接口，一处注册。事件是 span 级别的，不含 token 级增量。

```go
package observe

type Kind string // 核心定义 run / node / llm / tool / interrupt / checkpoint；扩展可自定义（如 retrieval、mcp）

type Event struct {
    Kind     Kind
    Phase    Phase                // start / end / error
    Name     string               // 节点名、模型名、工具名
    Trace    Trace                // TraceID、SpanID、ParentSpanID、RunID，沿用现有 callback.Trace
    Time     time.Time
    Duration time.Duration        // end、error 时有效
    Usage    *schema.TokenUsage   // llm end 时有效
    Err      error
    Attrs    map[string]any       // step、visit、finish_reason、tool_call_id 等少量结构化属性
}

type Observer interface{ OnEvent(context.Context, Event) }

func With(ctx context.Context, o ...Observer) context.Context
func Multi(o ...Observer) Observer
func Async(o Observer, buffer int, dropWhenFull bool) Observer
func Slog(l *slog.Logger) Observer
```

使用方式：

```go
ctx = observe.With(ctx, observe.Slog(logger))
out, err := app.Invoke(ctx, input)
```

要点：

- **默认不含载荷。** 事件只带元数据和大小，不带消息内容。需要看 prompt 和回复时，用 `observe.CapturePayload(redact)` 显式开启，并经过脱敏钩子。这同时覆盖审查报告 3.11。
- **同步为默认，异步显式。** 同步保证 `Invoke` 返回时事件已处理；`Async` 解决审查报告 2.6 的慢观察者阻塞问题。Observer 的 panic 被捕获并记录，不影响业务结果，这一点沿用现有 `callback.Manager` 的行为。
- **UI 流只是视图。** `pkg/stream` 的 lifecycle 事件由一个内置 Observer 适配产生，只保留一个发布点。
- **OTel 在扩展里。** `extensions/otel` 把 Event 转成 span，新依赖只进扩展模块，版本选发布满 7 天的稳定版。
- **现有 `callback.Trace`、`Begin` 迁入 `observe`，ID 体系不变。**
- **调用链属性贯穿所有事件。** 调用方在入口用 `observe.WithMetadata` 设置的键（例如 `tenant_id`、`user_id`）由 `Begin` 并入每个子操作，经 `EventOf` 进入事件 `Attrs`，再由 `extensions/otel` 导出为 span 属性。这是多用户场景按租户筛选调用链、统计用量的基础，后续重构不得破坏，约束见 5.6。

### 5.2 建图门面：泛型 State 加节点函数

在现有引擎上加一层薄门面，不另起运行时。节点直接读写 State，复用现有的 `StateNode`（<ref_snippet file="D:\Development\Go\goHarness\pkg\graph\state_node.go" lines="27-44" />）。

```go
type State struct {
    Messages []schema.Message
    Done     bool
}

g := graph.NewState[State]("research")
g.Node("plan", func(ctx context.Context, s *State) error { ... })
g.Node("search", func(ctx context.Context, s *State) error { ... })
g.Start("plan")
g.Branch("plan", func(ctx context.Context, s *State) (string, error) {
    if s.Done { return graph.End, nil }
    return "search", nil
}, "search", graph.End) // 声明允许的目标，Compile 据此校验节点存在与类型
g.Edge("search", "plan")

app, err := g.Compile(graph.Checkpointer(store))
out, err := app.Invoke(ctx, State{...}, graph.Thread("t1"))
```

要点：

- Builder 方法不返回 error，错误累积到 `Compile` 时用 `errors.Join` 一次返回，保留现有校验。
- 泛型参数承载 State 类型，类型错误在编译期暴露。
- 并行用 `g.Parallel(from, branches, join, reduce)` 映射到现有 Fork/Join，动态扇出用 `graph.Send`，对应现有 `AddDispatch`。
- 原有 `AddNode` 加 Pre/Post Handler 保留为高级用法，用于把 Agent 或其他 Runnable 接入图。
- **取消 `Command{Update, Goto}`（审查报告 4.2）。** 节点直接修改 State，跳转由 `Branch` 表达，`Resume` 已有，不再需要第二套控制流。取消后 `Branch` 是唯一的动态路由，因此有两个硬要求：
  - 目标必须预先声明（见上例），保证 Compile 期可校验、修订契约可哈希。
  - 路由函数每次决策只求值一次。现有引擎按边顺序逐条求值谓词（<ref_snippet file="D:\Development\Go\goHarness\pkg\graph\runtime_execute.go" lines="1406-1432" />），门面若把路由函数拆成 N 个谓词会求值 N 次，需要在引擎侧补一种“单次求值的路由边”。
- 门面只是语法糖，没有独立运行时。阶段四之后再评估是否与引擎合并。

### 5.3 泛型工具定义（审查报告 4.10）

`jsonschema-go` 已在依赖里，`jsonschema.For[T]` 可直接推导 schema（已核实该函数存在）。

```go
type SearchArgs struct {
    Query string `json:"query" jsonschema:"搜索关键词"`
    Limit int    `json:"limit,omitempty"`
}

search := tool.New("search", "搜索订单",
    func(ctx context.Context, a SearchArgs) (string, error) { ... },
    tool.ReadOnly())
```

保留现有 `NewFunctionTool` 作为底层入口。

### 5.4 Agent 收敛

- 入口只有 `agent.New(model, opts...)`：无工具是单次调用，有工具是 ReAct。
- **配置只留 Option 一种入口，删除 `BaseConfig` 的字段入口。** 这样 `WithToolRetries(0)` 的“显式零值”天然成立，不再需要 `toolRetriesSet`、`legacyRetriesSet` 等存在性标记（<ref_snippet file="D:\Development\Go\goHarness\pkg\agent\base.go" lines="48-72" />）。
- 删除别名 `MaxRetries`、`RetryBackoff`。
- 删除 `WithModelRetry`、`WithModelRateLimit`，以及只为它们存在的 `InspectModelPolicies`、`UnwrapModel` 和策略链检查。用户自己组合装饰器：`llm.NewRetryingModel(llm.NewRateLimitedModel(m), cfg)`，顺序由用户保证。
- Agent 对外接口只有 `Invoke`、`Stream`。
- `RoutingAgent`、`GroupChat` 作为基于图门面的示例保留，不再是公开类型。

### 5.5 检查点简化（阶段四，高风险）

目标语义：每个 superstep 保存 `(thread、state、next、pending interrupts)`。

- 图结构变化时只做整图指纹比对，不匹配则拒绝恢复，删除条目化契约和 `WithMigration`。
- 子图中断用 namespace 前缀区分，替代嵌套执行树。
- 保持 at-least-once 语义，文档继续如实说明。
- **必须保留两条并发保护。** 框架不提供分布式锁，多副本部署下同一会话同时到达两个请求时，只能靠这两条兜底：
  - 乐观版本冲突检测：`Store.Save` 版本不符时返回 `state.ConflictError`（`pkg/state/checkpoint.go`），Memory 与 Redis 两个实现都要保持。
  - 未完成运行的保护：会话存在失败或挂起的运行时，新输入返回 `state.ErrUnfinishedRun`，只有显式 `agent.WithAbandonUnfinished()`（内部调用 `state.AbandonRun`）才放弃旧运行。
- 先写出“行为契约清单”，再动代码。现有的 `checkpoint_resume`、`exec_tree`、`mode_parity` 测试是契约来源，上面两条并发保护也列入清单（对应测试见附录 D）。

### 5.6 多用户场景约束

框架对多用户的定位不变：提供隔离用的基础能力，注册、鉴权、限流和多副本调度属于应用层。轻量化不删除这些基础能力，但各阶段都要遵守下表。

| 关注点 | 框架提供 | 轻量化中的约束 |
| --- | --- | --- |
| 会话隔离 | 每次运行带会话 ID，存入 `state.Store`；文档建议 `tenant:user:session` 命名 | 不变 |
| 并发共用实例 | `CompiledGraph` 不可变，Agent 构造后可被多个请求并发调用 | 门面与 Agent 收敛不得引入实例级可变状态 |
| 工具鉴权 | `tool.Subject`（含 `TenantID`、角色、权限）、`RequireSubject` 与 Middleware | `tool` 包保留，不变 |
| 多副本并发同一会话 | 版本冲突检测与未完成运行保护；不提供锁 | 阶段四必须保留，见 5.5 |
| 存储的租户隔离 | 由应用拼接 key | 3.10 改为按需外置：做成 `state.Store` 装饰器扩展，给 key 加租户前缀并在加载时校验，可选加密；核心不变重 |
| 按用户观测 | `observe.WithMetadata` 设置的属性进入所有事件与 OTel span | 补一条端到端契约测试：一次 ReAct 运行中 run、node、llm、tool、checkpoint 事件的 `Attrs` 与 OTel span 属性都带入口设置的 `tenant_id`。现有测试（`graph_test.go`、`options_dispatch_test.go`、`tool/node_test.go`、`options_boundary_test.go`）只验证元数据传到节点与工具的 ctx，没有验证事件与 span |
| 隐私 | 事件默认不带载荷，`CapturePayload` 开启时经过脱敏钩子 | 不变 |
| 按用户控制成本 | 3.9 暂缓 | 应用用 Observer 累计 `Usage`，超限时通过 `context.WithCancelCause` 加 `control.RequestInterrupt` 中止当前运行；在 cookbook 中给出示例 |
| 模型限流 | 装饰器 `llm.NewRateLimitedModel` | 按 Agent 实例限流的 Option 已删除；按用户或租户限流仍属应用层 |

### 阶段一：统一观测

- 新增 `pkg/observe` 与 `extensions/otel`。
- 现有发射点只有 5 个文件（附录 B），在这些位置同时发出新事件（双发），验证后再删旧通道。新增 `interrupt`、`checkpoint` 两类事件的发射点。
- `stream` 的 lifecycle 改由 Observer 适配产生。

### 性能验收规则

以 `pre-slim` 为固定对照，每个阶段分别核对同名场景的 `ns/op`（耗时）、`B/op`（分配字节数）和 `allocs/op`（分配次数）。各取十次采样的中位数，增加比例为“阶段结果中位数 / 基线中位数 − 1”。三个指标分别判定，不把场景混成平均值，也不用某项改善抵消另一项退化；基线为零的指标要求保持零。前一阶段的记录可辅助定位，但不能取代固定对照，以免小幅退化逐阶段累积。

前后采样使用同一台机器、相同 Go 工具链、相同 fixture 与 benchmark 版本，以及相同场景输入和计时范围。统一采用 Full、`Count=10`、`Benchtime=1s`、`Cpu=1`，并保持 GOGC、GOMEMLIMIT、CGO 配置一致，在机器空闲时顺序运行。现有记录使用 Go 1.24.4；更换工具链时，先在新工具链上重跑 `pre-slim` 作为对照，并同时保存新的环境记录。

任一场景的任一指标增加超过 10%，先用上述条件重新采样对照版本与阶段版本，保留完整原始记录。复测仍有同一场景的同一指标超过 10% 时，该阶段暂不通过性能验收，需定位并修正后再测。首次超标而复测不再超标的，记录两次结果及环境情况；全部可比场景均满足规则后，性能检查通过。

新增能力使用独立场景，说明其成本；删除能力时在阶段记录中列明退出对比的场景。输入语义、计时范围或 fixture 改变的场景需要重新建立可比对照，不能直接拿旧数字判断变快或变慢。每阶段的原始记录、命令和代码身份按既有基准归档方式保存。

## 十、决策记录

### 已决策（2026-10-08）

**决策一：取消 `Command`（审查报告 4.2 的 Command 部分）。**

- 代码影响：无。`Command` 从未实现，Go 代码中没有引用（`extensions/mcp` 的 `Command` 字段与此无关）。
- 文档影响：审查报告 4.2（Command）标为取消；实施方案 4.9 中“可基于通用 `Command` 补充”的说法作废。
- 设计约束：`Branch` 成为唯一的动态路由，必须满足 5.2 的两条要求——目标预先声明、路由函数每次决策只求值一次（需要引擎侧补“单次求值的路由边”）。
- 放弃的能力：节点一次返回“更新加跳转”、跳到未声明的节点、从外部在没有挂起问题时改写 State、子图向父图跳转。恢复时携带答案由现有 `WithResume(id, answer)` 覆盖。

**决策二：Agent 配置只保留 Option 入口。**

- 代码影响：`BaseConfig` 在 37 个文件中出现 234 次；生产代码约 9 个文件（`agent` 的 `base.go`、`config_options.go`、`new.go`、`basic.go`、`react_agent.go`、`routing.go`、`hub.go`，`subagent/builder.go`，以及 3 个示例），其余约 25 个测试文件为机械改写。
- 公开签名变化：`agent.New(cfg, opts...)` 变为 `agent.New(model, opts...)`；`ReactAgentConfig`、`SupervisorConfig` 等嵌入 `BaseConfig` 的配置同步调整。
- 删除内容：四个存在性标记与 `resolveRetryAliases`、别名 `MaxRetries` 与 `RetryBackoff`、`WithModelRetry`、`WithModelRateLimit`、`model_policy.go` 及策略链检查。
- 与 2.9 的关系：2.9 已于同日验收，本决策会回退其中的模型策略和别名部分；工具侧的 `ToolNodeConfig.RetryBackoffSet` 保留，因为 `ToolsNode` 仍以结构体构造。
- 执行约束：
  1. 范围只限 Agent 层，`llm.Config`、`ToolNodeConfig` 等底层组件配置仍为结构体。
  2. 在阶段二用一个独立提交完成；先把 `model_policy_test.go` 中仍有价值的行为（显式零值、重试间隔、默认值）转成新 Option 的测试，再删除旧测试，避免覆盖丢失。
  3. 同一提交内确定初始化选项与单次运行选项的命名规则，消除 `WithMaxLLMCalls` 与 `WithRunMaxLLMCalls` 这类并存。
  4. README、使用手册、`tool-runtime.md`、`llm-providers.md` 中的示例同步改写。

**决策三：性能退化阈值为 10%。**

按同名场景的耗时、分配字节数、分配次数的十次采样中位数分别判定；任一指标增加超过 10% 时复测，复测仍超标则修正后再验收。固定对照、环境要求和场景变化的处理见[性能验收规则](#benchmark-gate)。

**决策四：子 Agent 选择选项 B 的精简版（2026-10-09）。**

- 形态：子 Agent 是“在工具调用里同步运行的子图”，放在 `extensions/subagent`。工具调用内的嵌套运行按调用身份成为子执行并写入独立命名空间记录，嵌套审批、已完成结果复用、兄弟完成态保留直接由契约清单 E 节覆盖。
- 保留：创建并等待（一次调用可并行多个）、子 Agent 内审批上报与恢复、部分完成部分待审批的恢复、重放不重复创建、跨轮会话子 Agent（命名空间会话 key）、创建者作用域、损坏记录拒绝、注册表约束。
- 放弃：后台异步任务模型，包括收件箱与补充消息、取消及级联取消、任务存活于创建节点之外、跨节点等待、与图批任务共享并发额度，以及对应的 `send_message`、`cancel_agent`、`wait_agents` 工具。逐条列在契约清单 K 节第 6 项。
- 硬性约束：扩展只用 `graph`、`agent`、`state`、`tool` 的公开 API；一旦需要访问引擎内部，先停下重新评估，不为扩展新增引擎扩展点。
- J3（abandon 回滚）已定：**接受语义变化，列入契约清单 K 节**。独立记录后扩展在 `state.AbandonRun`（含 `WithAbandonUnfinished` 内部路径）执行期间没有介入点，同步回滚物理不可能；惰性清理需给每条子 Agent 记录加 OwnerRunID 并在每次扩展调用时扫会话历史，复杂度与收益不成比例。abandon 本来就不回滚副作用（HTTP、工具写），子 Agent 会话记录同属其自身数据。元数据仍记录创建者 RunID，扩展提供显式 `Cleanup` 入口供用户在 abandon 后清理孤儿记录。
- 理由：
  1. 全部对等重实现等于把复杂度移出核心而不是删除，且多数异步语义依赖协调器内部，会迫使引擎扩大公开 API。
  2. 这些语义当初经过多轮复核才稳定，重写风险最高。
  3. LangGraph 本身没有内置异步子 Agent 管理器，子 Agent 即子图或工具，与“功能不求多”一致。
- 展示价值：完整的异步受管任务保留在 `pre-slim` tag，阶段五在《设计取舍》中说明拿掉的原因。
- 代码量：2026-10-09 核心非测试代码为 22,683 行（非空行口径）；三处待删文件合计 2,617 行，另有协调器、检查点等文件中约 166 行相关引用。全部删除后估计约 19.8k 至 20k 行，仍略高于 19k，需要在阶段四收尾时再找其他空间或在文档中调整目标。**收口结果**：删除后实测 20,879 行，再清死代码至 20,809 行；剩余为引擎与核心能力代码，无整包可移、无机械删减空间，验收目标按决议调整为 ≤ 21k 行。
