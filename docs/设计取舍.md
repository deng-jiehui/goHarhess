# 设计取舍

本文记录轻量化改造中被砍掉或外移的能力、理由与去向。完整的历史实现保留在
`pre-slim` git tag（`2335b1a`），过程文档在 `docs/design/archive/`。

## 砍掉什么，为什么

| 能力 | 处置 | 理由 |
| --- | --- | --- |
| RAG 组件 | `pkg/retrieval` → `extensions/retrieval` | 检索是应用级数据能力，不是编排引擎职责；核心不必携带向量存储、Embedding 适配的依赖与表面积。 |
| 后台受管子 Agent | 删除核心实现，`extensions/subagent` 重建 | 旧模型（异步任务、inbox、`send_message`/`cancel_agent`/`wait_agents`）把一套消息总线塞进引擎。新模型让子 Agent 在工具调用里**同步**运行：结果就是工具结果，复用引擎现成的嵌套执行、审批传播与恢复语义，零新增引擎概念。 |
| `AddParallelNode` | 删除 | 三套并行入口（普通边、`AddParallelNode` 包装、Fork/Join）收敛为 **Fork/Join + `Send`** 一套。`AddParallelNode` 只是 Fork/Join 的展开包装，删除后语义无损。基准场景名 `parallelnode` 保留作兼容口径，实际走同一路径。 |
| `WithMigration` / Codec 迁移 | 删除 | 条目化恢复契约改为**整图指纹**：拓扑、State Codec 身份与版本的任何变化都拒绝恢复，不给迁移豁免。项目尚未投入使用，维护一条"尽力迁移"的通道成本高于重新运行。 |
| `httpclient.Service`、`tool.NewHTTPService` | 删除，保留 `httpclient.Pool` | HTTP 服务封装不是核心能力；连接池保留供 LLM Provider 与检索适配器共享。 |
| Routing / GroupChat 配方 API | 删除 | `agent.New` 收敛为 Basic/ReAct 两种配方；主管路由与群聊用 `graph.NewState` 门面 + `AgentNode` 表达，见 `examples/routing`、`examples/groupchat`——编排不再是引擎内置的第二种图形态。 |
| 观测通道 | 6 套 → 1 套 | 旧 schema.MessageEvent、callback.EmitStream、internal/streamcompat 等全部删除。`pkg/observe` 是唯一生命周期观测入口，`pkg/stream` 是唯一实时数据通道；`observe.With` 一行接入。 |

## 外移但保留的语义

阶段四删除核心受管代码时，以下行为由扩展或等价机制接住，不是消失：

- **嵌套审批传播**：`extensions/subagent` 子 Agent 内的 `graph.Interrupt` 经命名空间
  执行树汇总到根运行，统一 `InterruptedError`，根入口 Resume 恢复；
  同批已完成的兄弟调用直接复用结果。
- **会话子 Agent**：记录以 `<conversationID>/agents/...` 独立键保存，跨轮沿用上下文；
  `abandon` 不再自动回滚子 Agent 记录（语义变化，见下），需要整洁时显式 `Cleanup`。
- **并行超步**：Fork/Join 与动态分派的完成成员复用、分批恢复、并发上限均保留，
  且统一受根图 `SetMaxConcurrency` 约束（含嵌套子图执行）。

## 接受的语义变化

- **Abandon 不回滚子 Agent 记录**：旧实现里 `SubAgents` 内嵌于检查点、随 abandon
  一并回退是存储形态的副产物，不是有意设计。子 Agent 的会话记录是它自己的数据，
  保留更诚实；要清理用 `subagent.Manager.Cleanup`。
- **恢复是 at-least-once**：维持原语义——中断节点与并行分支可能重放，副作用幂等
  始终是应用责任。框架不提供 Lease、fencing 或 exactly-once。
- **无检查点时中断直接报错**：`graph.ErrCheckpointRequired`，不做内存内假挂起。

## 行数账

- `pre-slim` 基线：核心非空非测试行 `pkg` 约 25.7k、`pkg+internal` 约 27.1k。
- 阶段四收口：`pkg+internal` **20,835**（含 `internal/benchfixture` 971）。
- 目标从 ≤19k 调整为 ≤21k：观测层、泛型门面与基准 fixture 是新增且必要的核心代码；
  机械删除空间已尽，继续压缩需要对引擎主干做有风险的结构合并，收益不成比例。
