# Graph 原生分支实施计划

目标：普通节点可以由 Graph 扇出执行，并在指定节点等待所有分支到达。保留 AddBranch 的首个命中语义和顺序流式执行能力。

1. 先补原生扇出、长短分支汇合、稳定合并、失败恢复的测试。
2. 增加 AddFork、AddJoin、SetStepMerger、SetMaxConcurrency。编译时检查所有分支路径必须到达对应汇合点，拒绝分支内循环、嵌套扇出和跨组连线。
3. 在现有唯一调度循环中引入任务批次。一轮共用入口快照，任务使用独立 State；全部成功后合并、路由、保存，再启动下一轮。顺序流式节点继续使用原数据面适配器。
4. 检查点保存轮次、累计任务数、下一轮任务及汇合到达记录。失败重跑未提交整轮；复用 sync/async 持久化语义，升级 continuation 版本。
5. 原 AddParallelNode 共用批次并发执行器，保留其合并函数及对外接口。
6. 验证任务预算、取消、外层循环再次扇出、编译限制和人工交互回归。运行核心、extensions 及 race 测试，再将实际完成范围写回审查报告。

暂不实现：动态 Send、字段级 reducer、分支成功结果单独落盘、并行人工交互。外部副作用和已经发送的流内容无法回滚。
